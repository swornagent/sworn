## Verdict

RC2 has no W5 implementation. Its T4 lineage materialised only W5's baseline
status over the composed W2 product. Every older provider implementation is
pattern archaeology coupled to a role-specific driver, `internal/model`, or
the retired adapter/executor architecture. None is safely replayable as RC3
W5 product bytes.

W5 must be implemented fresh under W2 v3's common role-neutral contract,
within `internal/driver`, with explicit per-role model selection and no
provider-specific lifecycle, retry, planning, recovery or Merge behavior.
There is no safe legacy cherry-pick sequence.

## Required RC3 repair boundary

Fresh W5 must:

- preserve W2 v3's rule that exactly one request-bound completed result exists
  before acknowledgement or provisional state;
- expose six profiles behind one common role-neutral driver, with model
  selected per role and no production Merge driver;
- use opaque domain-separated `CredentialRef` and private credential
  generation without retaining bytes or cleartext identifiers;
- pin native ELFs and certify their toolchain, libraries, CA, DNS, hosts, NSS,
  features and child credential blindness;
- bound native events, HTTP bodies, turns, tool calls, output and time;
- terminate the complete invocation after any `sworn_submit` attempt;
- reject unknown capabilities, redirects, implicit retries, SSE, streaming
  and AWS eventstream;
- keep DeepSeek reasoning out of tool arguments and handoff artifacts;
- implement Gemini function-call round trips and direct Bedrock SigV4 without
  provider SDK or module changes; and
- report each profile independently as PASS, NOT CERTIFIED or NOT RUN, with
  at least one credential-backed native PASS and one HTTP PASS for technical
  readiness.

Claude live readiness remains NOT CERTIFIED until every allowed tool child is
proved blind to authentication and provider credentials.

## Budget and safe next step

W5 growth is measured from W2's exact 3,277-line `internal/driver` baseline:

```text
0-2600 added runtime lines      normal band
2601-2800                       proof-backed Captain justification required
more than 2800                  newly approved replan required
```

Wait for W2's product candidate, fresh PASS and exact composition. Materialise
T4 through Baton from that frozen dependency head, write and Captain-review a
fresh W5 design, then implement under `internal/driver` using old tests only as
adversarial ideas.

Stop on old proof/verdict reuse, role-specific drivers, hosted inference or
proxying, provider SDK/module changes, unresolved capabilities, PATH/ELF or
runtime-closure drift, credential visibility, cleartext identifiers, implicit
retry/redirect, streaming, unbounded transport/tool/time behavior,
post-submit activity or inherited live certification.
